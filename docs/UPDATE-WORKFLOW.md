# 内容更新流程（SOP）

适用：`topics/` 下的项目索引页（如 `07-open-source-projects.md`）与首页 README 的周期性更新。

---

## 一、核心规则（先看这个）

### 1. 目录只保留一份，不单独设「最新亮点」板块

**❌ 错误做法**：在正文顶部单独开一个「🆕 最新亮点」板块，把新项目卡片堆在那里。

**✅ 正确做法**：

- 正文里**只有**「目录 + 四个分类」两层结构
- 新项目**直接收录到它所属的分类**（人形 / 四足 / 机械臂与桌面 / 移动 / SLAM / 抓取 / 具身模型 / 平台 / 训练框架 / 数据采集 / 教程）
- 目录里保留一个**精简的「本期新增」区块**，每个项目名**直接链接到所属分类的锚点**

这样读者点项目名 → 跳到分类 → 看到卡片和同类其他项目，而不是看到一个和正文割裂的孤立板块。

### 2. 目录可直接放到首页

「本期新增」这块目录设计成**可复制到 README 首屏**的形式，用来做更新播报。所以它要：

- 精简：一行放几个项目，不要一个项目一行带编号
- 可跳转：每个项目名都是链接，指向分类锚点
- 自解释：不带编号，靠项目名和括号里的简短说明

### 3. 首页更新描述要写清楚「加了什么」

**❌ 太笼统**：`新增七个机器人项目，涵盖核心功能、硬件方案与官方代码入口`

**✅ 具体要求**：按分类点出项目名 + 一句话特征，并让项目名可点击跳转。

示例：

```html
<kbd> 🆕 本周更新｜2026-11-04 机器人系统与开源硬件</a>：新增 7 个项目，
机械臂方向补入 <a href="...#hardware-arms">小楚君灵巧手（舵机拉线机械手）、RIG-Arm（带示教模式）…</a>；
四足方向补入 <a href="...#hardware-quadruped">XGO-Duck（Arduino UNO Q 双足鸭）…</a>；… </kbd>
```

> ⚠️ `<kbd>` **不要写闭合标签**。首页灰底背景依赖这个未闭合结构（GitHub 会把它延伸到段尾）。
> 一旦补上 `</kbd>`，灰框会收缩成文字大小，看起来就像「背景纹没了」。

## 二、标准流程

### 第 0 步：准备（一次性）

| 项 | 要求 |
|---|---|
| GitHub 权限 | 用 `Octoday-member0` 账号，或细粒度 PAT（只给目标仓库 `Contents: RW` + `Pull Requests: RW`） |
| 基线 | **永远从最新上游 main 开分支**，不要用本地落后的克隆 |

> ⚠️ 不要用个人账号的宽权限 PAT（带 `delete_repo`、`admin:org` 那种）。

---

### 第 1 步：对齐基线

```bash
cd <repo>
git fetch origin
git checkout -B update/<用途>-<日期> origin/main
```

**必须做**。否则可能把本地未推送的旧提交带进 PR，导致 diff 出现巨量删除。

---

### 第 2 步：确认新项目与分类

对每个新项目，先确定：

1. **归属分类**（决定卡片插到哪个 `####` 子章节）
2. **格式**（沿用该页现有卡片格式，不另创格式）
3. **封面图**（命名 `<owner>-<repo>.jpg`，统一 1200×630）
4. **GitHub 链接**（只放官方仓库；没有就写「暂未核实到官方 GitHub 仓库」）

**分类参考：**

| 项目类型 | 归入 |
|---|---|
| 人形 / 双足 | `硬件-humanoid` |
| 四足 / 多足 / 机器鸭 | `硬件-quadruped` |
| 机械臂 / 灵巧手 / 桌面机器人 | `硬件-arms` |
| 移动 / 无人机 / 水下 | `硬件-mobile` |
| Arduino 教程 / 知识库 | `数据-tutorial` |

---

### 第 3 步：写入内容

**卡片插入位置**：对应 `#### 子章节` 的**末尾**（原有列表条目之后）。

**目录更新**：在 `## 目录` 下维护「本期新增」区块：

```markdown
<a id="new-projects"></a>

- [🆕 本期新增（点项目名直达所在分类）](#new-projects)
  - [项目A](#hardware-arms) · [项目B](#hardware-arms) · [项目C](#hardware-arms)
  - [项目D](#hardware-quadruped) · [项目E](#hardware-quadruped)
  - [项目F](#hardware-humanoid)
  - 原有重点：[项目G](#hardware-arms) · [项目H](#hardware-humanoid)
```

**要点：**
- 按分类分组，一行多个项目用 ` · ` 分隔
- 每个项目名链向**分类锚点**，不是卡片锚点
- 保留「原有重点」一行，让老项目也还能跳
- 不带编号

---

### 第 4 步：同步中英文

英文页（`*_EN.md`）必须与中文页**一一对应**：

- 卡片数量、顺序、锚点一致
- 分类结构一致
- 链接集合零差异

---

### 第 5 步：跑校验

```bash
# 1. 标签平衡
# table/tbody/tr/td/p 开闭数量一致

# 2. 目录锚点全部可解析
# 每个 ](#xxx) 都能找到对应的 <a id="xxx">

# 3. 图片文件全部存在
# 每个 src="datasets-img/..." 都能找到实际文件

# 4. 中英文链接集合零差异

# 5. diff 无异常删减
git diff --stat
```

**diff 阈值判断**：如果删除行数明显接近或超过总行数的一半，**停下来检查**，通常是基线不对。

---

### 第 6 步：VS Code 里人工确认

```bash
code <repo>
```

按 ⌃⇧G 看 Source Control，逐个文件过 diff。

**重点看：**
- 新卡片是否在正确的分类下
- 目录链接是否指向正确的分类
- 有没有误删原有内容

---

### 第 7 步：更新首页 README

改 `README.md` 和 `topics/README_EN.md` 的更新横幅：

| 项 | 内容 |
|---|---|
| 日期 | 改为本次日期 |
| 数量 | 改为本次新增数量 |
| 描述 | 按分类点出项目名 + 特征，项目名可点击 |

**保持 `<kbd>` 不闭合。**

---

### 第 8 步：提交 PR

```bash
git add <只加本次相关文件>
git diff --cached --stat          # 确认没有多余文件
git commit -m "docs: ..."
git push fork <branch>
gh pr create --repo Octoday-Hub/Embodied-AI --base main --head Octoday-member0:<branch>
```

**PR 描述建议包含：**
- 新增项目列表（表格形式）
- 其他修正（如有）
- 检查结果表

---

### 第 9 步：后续（飞书同步）

> 格式待定，以下为约束条件：

- **单向同步**：Markdown → 飞书，不要双向
- 生成物先放草稿区，人工确认后再进知识库
- 飞书侧用**企业自建应用**，只开多维表格/文档读写权限

---

## 三、检查清单

更新提交前，逐项打勾：

- [ ] 分支从最新 `origin/main` 开出
- [ ] 正文无独立「最新亮点」板块
- [ ] 所有新卡片已归入对应分类
- [ ] 目录「本期新增」区块存在，链接指向分类锚点
- [ ] 中英文卡片数量、顺序、锚点一致
- [ ] 标签平衡（table/tbody/tr/td/p）
- [ ] 目录锚点无失效
- [ ] 图片文件全部存在
- [ ] `git diff --stat` 无异常删除
- [ ] VS Code 人工看过 diff
- [ ] README 中英文横幅都已更新（日期 + 数量 + 具体描述）
- [ ] `<kbd>` 未闭合（保持灰底）
- [ ] PR 只含本次相关文件

---

## 四、常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| PR diff 出现巨量删除 | 分支基于本地落后克隆 | 从 `origin/main` 重新开分支 |
| 首页灰框消失 | 给 `<kbd>` 补了闭合标签 | 去掉 `</kbd>` |
| 灰框在但字号太小 | `<kbd>` 自带 11px 等宽字体 | 这是 kbd 固有样式，要放大只能放弃灰框 |
| `style` 属性不生效 | GitHub 过滤 `style` | 不要用内联 style |
| 目录点击无反应 | 锚点名与实际 id 不一致 | 补 `<a id="...">` 别名 |
| 英文页图片缺失 | 移动卡片时漏了 `<p><img>` 块 | 逐张核对 |
| 卡片跑到错误分类 | 插入时定位到了下一个章节 | 用 `#### 标题` 到下一个标题的区间插入 |
